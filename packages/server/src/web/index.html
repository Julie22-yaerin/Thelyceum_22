The circuit breaker company

We stop AI before it costs you.

Three tools, done narrowly and well. brake stops a dangerous action. redteam stops a one-sided conclusion. thrift stops you paying for the same file twice. All three are always-on — the model calls them itself, with no slash command and no asking.

Built to sit on the hot path of a heavy agent harness, where the check runs on every single tool call and a slow guard is worse than no guard.

Fast enough to never be the bottleneck

If a safety check costs more than the work it guards, it gets switched off. So these are measured, not estimated — and the numbers below are asserted by the test suite, so they can't quietly rot.

1.37M
danger scans / sec
Single process, single core. p50 0.73µs, p99 0.93µs per call.
494k
reasoning challenges / sec
Single process, single core. p50 1.96µs, p99 18.4µs per call.
0
network calls on the hot path
Both scans are pure local computation. No API, no model, no round trip.
How these were measured. One million scanForDanger calls and 500,000 challenge calls over a mixed corpus of dangerous and benign inputs, after JIT warm-up, on a single core of an Apple Silicon laptop. Your hardware will differ — what matters is the order of magnitude, and that the regression tests in test/throughput.test.ts fail the build if either drops below a floor well under these figures.

What we are not claiming. These are the guard functions, which is where the cost would be if there were one. Actually engaging the brake does real work — killing tracked processes, running your stop script, posting your webhook — and is bounded by a measured 1000ms SLA instead, reported honestly when it is missed.

The headroom, in your terms

The question isn't "is it fast", it's "does it hold at my fleet size". Here is the arithmetic rather than an adjective.

A 500-agent fleet, one tool call each per second

500 agents × 1 call/sec = 500 scans/sec capacity, one core = 1,370,000 scans/sec utilisation = 0.04%
Uses well under 1% of a single core.

Added latency per guarded tool call

danger scan ≈ 0.73µs reasoning challenge ≈ 1.96µs combined ≈ 2.7µs a fast LLM round trip ≈ 300,000µs
Roughly 0.001% of the call it protects.

Three tools, one plan

They fail differently, so they are separate tools. One subscription covers all three.

brake

Stops the action.

Cuts the model off before it exfiltrates data, attacks infrastructure, reads a credential, destroys something irreversible, or moves money — 1000ms SLA, measured and reported. A brake that quietly took 3 seconds while the UI said 1000ms would be worse than no brake, so a miss is shown, never hidden. 

npm install -g brake
brake install all
Setup guide →

redteam

Stops the argument.

Scans a claim or plan for overconfidence, unsupported claims, confirmation bias, false dichotomies and missing trade-offs — then steelmans the other side, so the conclusion gets tested instead of asserted. Nine flaw classes; two of them block by default. 

npm install -g redteam
redteam install all
Setup guide →

thrift

Stops the bill.

Cuts the tokens an agent burns on its own tool output. The second read of an unchanged file returns a pointer, not the file — which is where the saving actually is. 78.5% measured on an agent loop, 97.6% of it lossless. On a first pass over unique files it saves almost nothing, and the docs say so rather than quoting the flattering number. 

npm install -g thrift
thrift measure . --passes 5
